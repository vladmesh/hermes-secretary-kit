# Memory library

Plain markdown, one note per file. The agent reads it top-down and never loads
everything at once.

| Level | File | Read when |
|---|---|---|
| 0 | `MEMORY.md` / `USER.md` in the Hermes profile | always in the prompt |
| 1 | `INDEX.md` | first step of any recall |
| 2 | `<section>/_index.md` | INDEX points at a section |
| 3 | the note itself | one file at a time |

Levels 1 and 2 are generated by `reindex.py` from frontmatter. Do not edit them by hand.

## Note format

    ---
    name: kebab-case-slug
    description: one line, this is what search sees
    type: fact | person | project | journal
    tags: [a, b]
    updated: 2026-01-15
    ---
    Body. Link other notes as [[slug]].

## Sections

- `facts/` - stable facts about the owner's world: servers, accounts, habits, agreements.
- `people/` - one file per person.
- `projects/` - one file per project, what it is and where it stands.
- `journal/` - dated notes `YYYY-MM-DD-topic.md` plus the running `notes.md`.

Rebuild indexes: `python3 reindex.py`. Check in CI: `python3 reindex.py --check`.

Everything in this template is fictional.
